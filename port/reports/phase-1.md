## Notes (added by hand after the generated report)

- **Boundary.** Source maps cross napi in bulk: module tuples go over as one `Int32Array` (5 values per mapping, names as an index into a per-batch string table, batches of at least 32768 mappings), VLQ module maps as strings, and the `SourceMapEncoder` class keeps the generator state between batches. Decoding writes into a reused scratch `Int32Array` that is not retained. `composeSourceMaps` interns sources and names to ids in JS and sends decoded columns. Sources, `sourcesContent`, `x_facebook_sources` and `x_google_ignoreList` are still assembled in JS, so key order is the JS key order.
- **Fallbacks to JS (results and errors stay the JS ones).** Malformed VLQ, non-string names, unsorted compose input, invalid compose mappings, index maps inside compose, and a missing or unreadable file in `getCacheKey` (Node's own error is thrown).
- **Kept in JS.** `BundleBuilder` (measured through napi: 57-70 ms in Rust against 50-57 ms in JS for `measureString`), `toBabelSegments`, `tuplesFromBabelDecodedMap`, `generateFunctionMap` and `functionMapBabelPlugin` (these walk Babel AST and function metadata, per the task).
- **ob1.** Ported as the Rust crate `metro-rs-ob1` and used only inside the source-map crate (newtypes `Number0` and `Number1`, wrapping arithmetic like the JS). The JS package `ob1` is unchanged: a one-line arithmetic helper across napi would cost about 50 ns a call and gain nothing, so nothing in JS calls Rust for it.
- **core.** `canonicalize` is a `JSON.stringify` replacer that V8 calls once per value. Measured here: one JS call on a small options object takes about 620 ns, while an empty napi call already costs about 54 ns and converting the object in and out would need a napi call per key, so a Rust version cannot be faster. `Logger` and `Terminal` are I/O (stdout, TTY, reporters), and the error classes are plain JS classes that callers `instanceof`. `metro-rs-core` is therefore left as the version crate. `port/phases.json` is unchanged and still lists `core` for this phase; the switch for `core` selects nothing to port.
- **Crates.** New: `md-5` 0.10 (cache-key). Dev-dependency only: `serde_json` 1 (reads the fixtures in `cargo test`). napi, napi-derive and napi-build were already in the workspace.
- **Flaky test seen once.** `port/blackbox/__tests__/hmr-protocol-test.js` failed once inside a loaded full Jest run in Rust mode; it passed alone in both modes and in every gate run.
- **Compile-time cost.** `eslint .` took several minutes while a helper file contained literal U+2028 characters; they are now ` ` escapes.
